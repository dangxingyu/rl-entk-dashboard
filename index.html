0结论速览At a glance

一句话：RL 在“到哪里”上大体 lazy，在“怎么到”上不 lazy。post-trained 0.6B 和 1.5B 上 linear 与 real 在噪声内（中期）。Base 0.6B 上 linear 拿到 real 大部分增益，落后在两处：takeoff 的尾部更晚；takeoff 之后低 .018-.038，约为 real 增益的 14%，最集中在 base 模型解出率 5-30% 的题。real 自己的更新离 θ₀ 的切线很远（切线只拿到 −.01 到 .74 的增益）；linear 是在切线附近找到了另一个解，逐题提升和 real 一致（相关 .765，两个 real seed 之间 .740）。差距不是温度，也不比两个 real seed 之间更集中在某类 token；kernel 移动（H8）正在检验。数据截至 2026-11-09 12:31 PST，仍有 run 在跑。

In one line: RL is largely lazy in where it ends up, not in how it gets there. On post-trained 0.6B and 1.5B, linear is within noise of real (interim). On Base 0.6B linear gets most of real's gain and lags in two places: a later takeoff tail, and after takeoff a deficit of .018-.038 (about 14% of real's gain), largest on problems the base model solved 5-30% of the time. Real's own update is far from the θ₀ tangent (the tangent recovers only −.01 to .74 of its gain); linear finds a different solution near the tangent, and it improves on the same problems as real (correlation .765, vs .740 between two real seeds). The gap is not temperature, and it is no more concentrated in a token class than between two real seeds; kernel movement (H8) is being tested. Data as of 2026-11-09 12:31 PST; runs still going.

1设置Setup

real 和 linear。两个 arm 的数据顺序、优化器和奖励都一样，区别只在策略怎么依赖参数。同一 seed 编号下 real 和 linear 用不同的采样 key（如 s1：real 1002，linear 1003）；共享 key 的是不同形式（见运行规则）。real 是普通网络 π_θ。linear（π_lin）是 θ₀ 处的精确一阶切线：π_lin(δ) = softmax(z₀ + J(θ₀)δ)，Jδ 用精确 JVP 计算，Adam 作用在 δ 上。linear 用自己的策略采样，所以它是完整的 RL，只是被限制在 θ₀ 的切空间里。

Real and linear. The two arms share data order, optimizer and reward; they differ only in how the policy depends on the weights. At the same seed index real and linear use different sampling keys (s1: real 1002, linear 1003); keys are shared across forms, not arms (see the run rules). Real is the ordinary network π_θ. Linear (π_lin) is the exact first-order tangent at θ₀: π_lin(δ) = softmax(z₀ + J(θ₀)δ), with Jδ from an exact JVP and Adam acting on δ. Linear samples from its own policy, so it is full RL restricted to the tangent space at θ₀.

这里的“lazy”指两个不同的问题。一是更新本身是否线性：把 real 训练出的 δ 放到 θ₀ 的切线上，能否预测真实网络沿同一 δ 的行为（Q3：插值和开环 capture）。二是行为能否由线性模型达到：直接训练 linear，它的准确率能否追上 real（Q1、Q2）。两个问题的答案可以不同，这里就是：更新本身不 lazy（Q3），linear 却能拿到 real 的大部分增益（Q1、Q2）。

“Lazy” means two separate questions here. First, is the update itself linear: placed on the tangent at θ₀, does real's trained δ predict what the real network does along that δ (Q3: interpolation and open-loop capture)? Second, is the behaviour reachable by the linear model: trained directly, does linear reach real's accuracy (Q1, Q2)? The two can have different answers, and here they do: the update is not lazy (Q3), yet linear gets most of real's gain (Q1, Q2).

术语。δ：参数相对 θ₀ 的位移，θ = θ₀ + δ；real 的 δ 是 θ_t − θ₀，linear 训练的就是 δ。eNTK：θ₀ 处的经验 NTK，由 J(θ₀) 给出；π_lin 就是 kernel 固定在 θ₀ 的模型。α：直线 θ₀ + αδ 上的位置，α=1 是训练终点。切线占比：α=1 时 (π_lin(δ) − π₀) / (网络(θ₀+δ) − π₀)，各项为准确率，π₀ 取该 run-step 自己的 α=0 格，只在网络增益 > .05 时计算。开环 capture：1 − KL(π_t‖π_lin) / KL(π_t‖π₀)，即把 real 的 δ 放进 θ₀ 处的切线，能复现 real 策略变化的多少。takeoff：Base 起初只写短答案，T=0.6 准确率停在 update-0 基线 .351 附近；某次 eval 和下一次 eval 都比基线高至少 .10，就记为在这次 eval takeoff（parity 规则，analysis/rz2-parity-rule.md）。k：takeoff 之后的 update 数。rows：每次 update 的样本行数，32 个 prompt × 4 个样本 = 128；rows 杠杆用 1,024（256 × 4）。形式：sync v4、sync v5p、async（行为策略最多落后 2 步）、lag 2、GB200。Part I：项目早先的 PyTorch + vLLM 实现；本页的 rz2 run 是 JAX fp32。假设编号沿用分析文档：H2 差距只是 takeoff 推迟（平台这一半已证伪）；H3 rows 杠杆；H4 温度/熵（linear 只是不够尖锐）；H4′ 差距集中在某类 token；H7 插值问题（248d198）；H8 差距需要 kernel 移动（Q5）。

Terms. δ: displacement from θ₀, θ = θ₀ + δ; real's δ is θ_t − θ₀, and linear trains δ directly. eNTK: the empirical NTK at θ₀, given by J(θ₀); π_lin is the model with the kernel frozen at θ₀. α: position on the line θ₀ + αδ; α=1 is the trained endpoint. Tangent share: (π_lin(δ) − π₀) / (net(θ₀+δ) − π₀) at α=1, all in accuracy, with π₀ the run-step's own α=0 cell, computed only where the network gains more than .05. Open-loop capture: 1 − KL(π_t‖π_lin) / KL(π_t‖π₀), how much of real's policy change the θ₀ tangent reproduces from the same δ. Takeoff: Base starts with short answers, near the update-0 pool of .351 at T=0.6; a run takes off at the first eval where it and the next eval are both at least .10 above the pool (parity rule, analysis/rz2-parity-rule.md). k: updates since the run's own takeoff. Rows: sample rows per update, 32 prompts × 4 samples = 128; the rows lever uses 1,024 (256 × 4). Forms: sync v4, sync v5p, async (behaviour policy up to 2 updates stale), lag 2, GB200. Part I: the project's earlier PyTorch + vLLM implementation; the rz2 runs here are JAX fp32. Hypothesis labels follow the analysis doc: H2 the gap is only a takeoff delay (plateau half falsified); H3 the rows lever; H4 temperature/entropy (linear is under-sharpened); H4′ the gap sits in a token class; H7 the interpolation questions (248d198); H8 the gap needs kernel movement (Q5).

运行规则。每个集合最多 2 个 seed（早期 TPU Base sync、async 和 lag 2 各跑了 4 个；1.5B v5p 有一个短的 s2，已 hold）；seed 编号（s0、s1…）在 sync v4、v5p、async、lag 2 和 GB200 之间共享采样 key，所以各形式不是独立重复。GPU 结果从不与 TPU 合并（例外见 Q2）。主指标是 math500fast：MATH-500 中 128 题 × 4 个样本，T=0.6，每 50 个 update 一次；一次 eval 的二项 s.e. 至多 .022，两次 eval 之差为 .031。精度闸门：fp32 权重，采样器和学习器的矩阵乘用 HIGHEST，v4 上有精度守卫；Jacobian refresh 启动前通过了闸门检查（见下表）。

Run rules. At most 2 seeds per set (early TPU Base sync, async and lag 2 each ran 4; 1.5B v5p has a short s2, held); the seed index (s0, s1, …) shares sampling keys across sync v4, v5p, async, lag 2 and GB200, so forms are not independent replicates. GPU sets are never pooled with TPU (exceptions noted in Q2). The headline eval is math500fast: 128 MATH-500 problems × 4 samples at T=0.6, every 50 updates; one eval has binomial s.e. at most .022, a difference of two evals .031. Precision gates: fp32 weights, HIGHEST matmul precision in sampler and learner, a precision guard on v4; the Jacobian refresh passed its gates before launch (table below).

噪声尺子（详见 §3）。一次 eval 的二项 s.e. 至多 .022，两次 eval 之差 .031；同一权重换 key 重评，rms .018；平台期两个 real seed 相差 .007-.026；同 key 分别在 v4 和 v5p 上训练，中位数相差 .033（最大 .246，来自 takeoff 时间不同）。一个差值要超过这些才算数。

Noise yardsticks (details in §3). One eval has binomial s.e. at most .022, a difference of two evals .031; the same weights re-evaluated under other keys differ by rms .018; two real seeds differ by .007-.026 on the plateau; the same keys trained on v4 and on v5p differ by a median .033 (max .246, from different takeoff times). A difference has to beat these to count.

差距是温度或某类 token 造成的吗？Is the gap a temperature or a token class?

Neither. No eval temperature closes the gap: the gap at each arm's best temperature is 0.96 of the T=.6 gap (the prediction needed ≤ 1/3), and real is above linear at every T. On shared tokens, real and linear disagree mostly at forks, as two real seeds do; stop and answer-box tokens together are no more prominent than between two real seeds (the pre-registered test).
